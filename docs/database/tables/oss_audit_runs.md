# OssAuditRuns

The OSS audit run table, recording each audit job's execution state and results.

## Table information

| Property | Value |
|------|------|
| Table name | `OssAuditRuns` |
| Database | `ruoyu_admin` (PostgreSQL) |
| Entity class | `Admin.WebApi.Persistence.OssAuditRun` |
| DbContext | `AuditDbContext` |

## Field definitions

| Field | Type | Constraint | Description |
|------|------|------|------|
| `Id` | `bigint` | PK, GENERATED ALWAYS AS IDENTITY | Primary key, generated by the database |
| `StartedAt` | `bigint` | NOT NULL | Audit start time (Unix seconds) |
| `CompletedAt` | `bigint` | NULL | Audit completion time (Unix seconds), null while running |
| `Status` | `int` | NOT NULL, DEFAULT 0 | Run status, see the enum below |
| `NewZombieCount` | `int` | NOT NULL, DEFAULT 0 | v1: the number of new read-only observations in this run; old runs keep the historical meaning |
| `TriggerType` | `text` | NOT NULL, DEFAULT 'scheduled' | Trigger: `scheduled` (timer) / `manual` (manual) |
| `ErrorMessage` | `text` | NULL | A fixed safe reason on failure |
| `ReferenceContractVersion` | `text` | NULL | `storage-references-v1` for new complete run records; null for old run records |
| `ReferenceSnapshots` | `text` | NULL | The JSON of complete snapshot metadata from Student, Mistake, and Homework; null for old run records |

## Status enum

| Value | Name | Description |
|----|------|------|
| 0 | `Running` | Running |
| 1 | `Completed` | Completed |
| 2 | `Failed` | Failed |

## Indexes

| Index name | Field | Type | Description |
|--------|------|------|------|
| PK | `Id` | UNIQUE | Primary key index |
| IX_OssAuditRuns_StartedAt | `StartedAt` | NON-UNIQUE | Sort queries by start time |

## DDL (PostgreSQL)

```sql
CREATE TABLE IF NOT EXISTS "OssAuditRuns" (
    "Id"            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    "StartedAt"     bigint  NOT NULL,
    "CompletedAt"   bigint  NULL,
    "Status"        integer NOT NULL DEFAULT 0,
    "NewZombieCount" integer NOT NULL DEFAULT 0,
    "TriggerType"   text    NOT NULL DEFAULT 'scheduled',
    "ErrorMessage"  text    NULL,
    "ReferenceContractVersion" text NULL,
    "ReferenceSnapshots" text NULL
);

CREATE INDEX IF NOT EXISTS "IX_OssAuditRuns_StartedAt" ON "OssAuditRuns" ("StartedAt");
```

## Business rules

- The two checks around creating a run record serve only in-process triggering; they guarantee neither durable queuing nor recovery after process termination — the boundary is in [pending decisions](../../pending-decisions.md).
- When validation of any of the Student, Mistake, or Homework complete snapshots fails, the run record is set to `Status=2` before any S3 listing; an S3 listing or database transaction failure fails the run likewise. On cancellation `audit_cancelled` is saved; other business failures save only `references_or_scan_unavailable`.
- The three sets of metadata, the version, the new observations, and the completed run record are committed together for a complete scan; no new-version reference snapshots or validation results are fabricated for old run records. When a non-empty `ReferenceSnapshots` exists, `Down` refuses to run, to avoid losing history.
- `Id` stays `GENERATED ALWAYS AS IDENTITY`; for the migration order see [migrations](../migrations.md).

## Relationship with OssAuditRecords

There are **no foreign keys** between `OssAuditRuns` and `OssAuditRecords`. They are associated through business logic:

- One audit run (`OssAuditRun`) inserts new read-only observation records into `OssAuditRecords`
- But `OssAuditRecord` does not record which `OssAuditRun` discovered it
- This design means a given audit record cannot be directly traced back to the run that produced it
