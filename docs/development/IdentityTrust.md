# Identity trust

The old explicit-issuer JWT consumption stack of `Ruoyu.Admin.Common` (`AddRuoyuJwtBearer`, `IdentityTokenValidationParametersFactory`, `IdentityAuthenticationOptions*`, `ClaimsPrincipalExtensions`, `RoleConstants`) has been deleted (#103): that stack was never registered in `Program.cs`, and the inbound authentication path is unchanged before and after the deletion.

Admin's only inbound authentication is the server session + `SignaCore.Client.AspNetCore` hosted OIDC; issuer trust is independently constrained by that client package through `IdentityService:Authority`: the discovery issuer must be same-origin with the Authority and the token issuer is checked exactly. `AdminSessionAccessor` reads the server ticket and does not validate browser JWTs; any inbound Authorization gets a fixed 401, and there is no browser-JWT fallback mode. For the only-server-session mode, see [Deployment.md](./Deployment.md).

Verification entry points: `backend/Tests/Integration/AdminOidcTests.cs` covers wrong issuer, bad metadata, cancellation, and zero-ticket regression; `AdminSessionApiTests.cs` and `AdminAssociationSessionTests.cs` configure "Bearer" scheme options in the test host and assert its authentication callback never fires (a canary for the "Bearer" scheme). The former `IdentityTokenValidationParametersFactoryTests` and `ExplicitIssuerJwtBearerTests` tested the deleted public helper contracts and were removed with them.

## Mistake outbound server ticket

When `MistakeService:UseSessionToken=true`, the dedicated handler calls `AdminSessionAccessor.AuthenticateAsync` in the current request scope on every send and additionally reads the current `ITicketStore` ticket. The framework's same-request authentication cache, `HttpContext.User`, TrustedSessionKey, or a pooled handler cannot substitute for the latest ticket; ticket rotation, revocation, a bad stamp/issuer, removal from the current allowlist, a missing/malformed token, or expiry are all rejected before sending. Only the server access token is sent, to the fixed HTTPS Mistake origin and the existing method/paths, with Cookies/redirects/loggers/telemetry disabled; the AppSecret is never used as a user identity. `false` keeps only the original anonymous Mistake compatibility and does not change the permanent inbound Session-only rule.

The target Mistake must independently trust the exact Issuer/Authority, the ADMIN audience, and the required roles. Passing Admin's local allowlist does not guarantee target authorization: a real target 401/403 is a safe 502 for Admin. Detail-GET 404, legitimate empty results, and explicit business 400/409 are handled distinctly from authentication/transport failures. For configuration, cancellation/single-send, and real-combination acceptance requirements, see [Deployment](./Deployment.md#mistake-outbound-session-ikjnxa).
